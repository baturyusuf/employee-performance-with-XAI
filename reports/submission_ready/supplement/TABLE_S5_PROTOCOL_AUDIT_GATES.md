# Supplementary Table S5. Protocol / Audit Gates

This table operationalizes the study's integration contribution. A gate defines what must be true before the corresponding manuscript claim can be made; it is not a claim that the individual methods are novel.

| Audit stage | Input | Required procedure | Output | Failure condition | Claim boundary |
| --- | --- | --- | --- | --- | --- |
| Information contract | Raw feature schema and declared prediction context | Classify identifier, outcome-proximal, sensitive, timing-uncertain, and organizational-proxy fields; record retained features for P0-P5 | Versioned feature-policy contract | Undocumented feature inclusion/exclusion or unsupported availability claim | Policies are assumption-based sensitivities, not proof of leakage freedom or prospective availability |
| Nested selection | Outer/inner fold identities and candidate registry | Fit preprocessing and select candidates only inside outer-training data | Exactly one selected candidate per model/outer fold | Outer-test outcomes influence preprocessing, tuning, calibration, seed, or policy choice | Supports within-run model-selection separation, not preregistration of the broader research program |
| Held-out prediction identity | Persisted outer models and test assignments | Generate exactly-once OOF hard labels and probabilities | One held-out prediction record per sample/system | Duplicate/missing OOF rows or sample/fold mismatch | Reported benchmark metrics apply only to the declared folds, systems, and hard-decision rules |
| Ordinal and extreme-class evaluation | OOF predictions and ordered labels | Report macro-F1/balanced accuracy with QWK, ordinal MAE, probability metrics, and per-class results | Aggregate plus classwise metric set | Aggregate score reported without class-support/extreme-class visibility | Good QWK/MAE does not imply acceptable rating-4 recognition |
| Prediction-explanation identity | Exact fitted outer model and held-out sample | Compute TreeSHAP from the same model that generated the prediction; aggregate encoded features by declared family | Fold-bound explanation evidence | Explanation produced from a different/full-data model | SHAP describes fitted-model attribution, not causality or actionability |
| Explanation robustness | Fold/seed/resample models and deletion rule | Separate ranking stability from masking/deletion diagnostics | Stability and deletion summaries | Stability interpreted as causal validity or masking as real intervention | Internal model-consistency evidence only |
| Probability quality | Outer-training cross-fitted probabilities and untouched outer test | Fit calibrators using outer-training data only and assess multiple calibration/probability metrics | Raw vs calibrated probability-quality results | Calibrator fitted using outer-test outcomes or one scalar metric presented as complete calibration evidence | Retrospective probability diagnostics; no prospective reliability claim |
| Subgroup / proxy boundary | Prespecified attributes, support rules, OOF outputs | Report all attributes, eligibility, exploratory simultaneous intervals; keep proxy reconstructability separate from model-use diagnostics | Support-aware subgroup and proxy evidence | Unsupported groups hidden, reconstructability equated with discriminatory use, or descriptive intervals treated as confirmatory tests | Descriptive diagnostics, not fairness certification, discrimination proof, or legal compliance |
| Cross-dataset / target mapping | HRDataset_v14, exact seven-feature policy, mapping definitions | Refit within the second dataset; evaluate mapping and CV-design sensitivities separately | Partial cross-dataset protocol replication | Described as locked-model transport, full protocol replication, or target equivalence | Dataset-specific replication/sensitivity only |
| Evidence traceability | Aggregate outputs, manuscript claims, source records | Bind numerical claims to versioned paths, selectors, values, qualifiers, and content hashes | Supplementary Evidence Ledger | Manuscript number lacks a resolvable source record or stale value survives validation | Traceability supports auditability; it does not resolve upstream dataset authenticity or redistribution rights |
